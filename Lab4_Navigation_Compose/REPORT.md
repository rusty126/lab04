## 3. Ход выполнения работы

### 3.1. Подключение библиотек
В файл `app/build.gradle.kts` добавлены зависимости Compose BOM, Material 3, Activity Compose, Navigation Compose и Lifecycle Runtime Compose. Для навигации используется библиотека `androidx.navigation:navigation-compose`.

### 3.2. Создание модели данных
Создан файл `User.kt` с классом данных `User`. Модель содержит поля `id`, `name`, `age`, `city` и `email`. Для проверки приложения подготовлен список из шести пользователей.

### 3.3. Создание списка пользователей
В `UserListScreen.kt` реализован экран со списком пользователей. Для эффективного отображения элементов используется `LazyColumn`, а каждый элемент представлен компонентом `UserCard`. Нажатие на карточку запускает маршрут `user_detail/{userId}` и передаёт идентификатор выбранного пользователя.

### 3.4. Настройка навигации
В `NavGraph.kt` создан `NavHost` с начальными и дополнительными маршрутами. `rememberNavController()` создаёт контроллер навигации. Аргумент `userId` объявлен через `navArgument` с типом `NavType.IntType`, после чего считывается из `backStackEntry.arguments`.

### 3.5. Детальный экран
В `UserDetailScreen.kt` по идентификатору находится пользователь и отображаются его имя, возраст, город и электронная почта. Если пользователь не найден, показывается сообщение. Кнопка со стрелкой назад вызывает `popBackStack()`. При открытии профиля отображается Snackbar.

### 3.6. Дополнительный экран редактирования
Добавлен экран `UserEditScreen`. После изменения имени оно передаётся предыдущему экрану через `previousBackStackEntry?.savedStateHandle`, затем выполняется возврат. Это демонстрирует механизм передачи результата назад по стеку навигации. В учебном примере исходный список является демонстрационным и не сохраняет изменения в постоянном хранилище.

### 3.7. Состояние и жизненный цикл
В экране списка применён `rememberSaveable` для хранения состояния фильтра. В `MainActivity` переопределены методы `onCreate`, `onStart`, `onResume`, `onPause`, `onStop` и `onDestroy`; их вызовы выводятся в Logcat с тегом `ActivityLifecycle`.

## 5. Контрольные вопросы

**1. Какие состояния жизненного цикла Activity вы знаете?**  
Основные callback-методы: `onCreate()` — создание Activity; `onStart()` — Activity становится видимой; `onResume()` — Activity выходит на передний план и готова к взаимодействию; `onPause()` — теряет фокус; `onStop()` — становится невидимой; `onDestroy()` — Activity уничтожается. Это методы обратного вызова, описывающие переходы жизненного цикла.

**2. Что такое NavController и для чего он используется?**  
`NavController` — объект, который управляет переходами между пунктами навигации, хранит стек экранов и предоставляет методы `navigate()` и `popBackStack()`.

**3. Как добавить навигацию в Compose-проект?**  
Нужно добавить зависимость `androidx.navigation:navigation-compose` в Gradle, создать `NavController` через `rememberNavController()` и описать маршруты внутри `NavHost`.

**4. Как передать данные между экранами в Navigation Compose?**  
Для простых данных можно добавить аргумент в маршрут, например `user_detail/3`, объявить его через `navArgument` и получить из `backStackEntry.arguments`. Для сложных объектов обычно передают идентификатор, а данные получают из общего источника или ViewModel.

**5. Что такое NavHost и как он работает?**  
`NavHost` — контейнер, который показывает composable-экран, соответствующий текущему маршруту. Внутри него задаются маршрут по умолчанию и остальные destinations.

**6. Как создать composable-маршрут с аргументом?**  
Нужно вызвать `composable(route = "user_detail/{userId}", arguments = listOf(navArgument("userId") { type = NavType.IntType }))`, а затем считать значение аргумента из `NavBackStackEntry`.

**7. Как вернуться на предыдущий экран?**  
Вызвать `navController.popBackStack()`. Этот метод удаляет текущий экран из стека и возвращает предыдущий.

**8. Что такое LazyColumn и в чём его преимущество перед Column?**  
`LazyColumn` — вертикальный список, который создаёт и отображает элементы по мере необходимости. В отличие от обычного `Column`, он подходит для длинных списков, поскольку не обязан одновременно размещать все элементы.

**9. Как обработать клик по элементу списка?**  
Можно использовать `Modifier.clickable { ... }`. В приложении клик по карточке вызывает `navController.navigate("user_detail/${user.id}")`.

**10. Как сохранить состояние списка при повороте экрана?**  
Для простых UI-значений применяется `rememberSaveable`. Для более сложного состояния используют `ViewModel` и, при необходимости, `SavedStateHandle`. Сам список данных обычно хранится в репозитории или другом источнике данных.
